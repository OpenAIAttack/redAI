SPEC AMBIGUITIES (for docs/implementation-decisions.md)
  - No UNAUTHENTICATED "owner exists" endpoint. docs/13 §1 wants /setup to check
    owner-exists, but the browser can only tell "valid session" vs "401". /setup thus
    probes /auth/session and explains the CLI bootstrap; it cannot distinguish
    "no owner yet" from "not signed in". Minimal fix: add GET /api/v1/auth/bootstrap-state
    returning { owner_exists }.
  - No owner-facing worker LIST API (only per-project bindings + enrollment). /workers
    is an honest info page; a list appears when the API lands.
  - No API for owner password change / session list-revoke from the browser (docs/13 §4
    Security). Handled as host-CLI ops and stated honestly; sign-out uses the real
    server-side logout.
