BEHAVIOR
  Durable artifact lifecycle over a DB row + local ObjectStore bytes:
    createUpload  -> `pending` row, logical storage_key reserved (ws/project/artifactId), no bytes
    putContent    -> bytes streamed into staging/<artifactId> (still pending), byte-capped
    finalize      -> server computes sha256+size over OBSERVED bytes, verifies vs the client-
                     declared values, ATOMIC rename staging -> objects/<key>, then commits the row
                     to `ready` (or `quarantined` when bytes contradict the declared media type)
    download      -> streams verified bytes; only a `ready` row is ever served (no public orphan),
                     as attachment + `X-Content-Type-Options: nosniff` (untrusted bytes never render)
    preview       -> bounded, HTML-escaped, secret-redacted, safe preview for
                     text/markdown/json/yaml/csv/png/jpeg only; others -> 415; never fetches externals
  Safety: path-traversal / absolute / symlink / bad-char keys rejected; writes stay inside the
  configured root; disk-full / IO / interrupted publish leaves the row `pending` (never a partial
  `ready`); finalize is idempotent (a duplicate returns the current row, no double-ready) and
  crash-recoverable (a rename-then-crash retry re-verifies the published object); reconciliation
  sweeps rowless orphan objects + stale staging and reports `ready` rows whose bytes went missing.
  Cross-project isolation is structural: every op threads (workspaceId, projectId, artifactId) so a
  foreign id resolves to 404 (INV-001). INV-007: a finalized payload is immutable (DB trigger +
  pending-only markReady).

SPEC AMBIGUITIES RESOLVED
  1. The frozen public.openapi.yaml addresses get/content/finalize at a FLAT `/artifacts/{id}`
     (only list/create are project-scoped). T07 explicitly REQUIRES cross-project isolation on
     download/preview as a test, and the whole codebase addresses project-level entities under
     `/api/v1/projects/:projectId/...` (T06). AGENTS.md priority: INV-* / permission boundaries win
     over an API sketch. Resolution: ALL artifact routes are project-scoped
     (`/api/v1/projects/:projectId/artifacts[/:artifactId][/content|/finalize|/preview]`), so
     project A's URL with project B's artifact id is a composite-key 404, never a cross-project read.
  2. `artifacts.kind` is NOT NULL with no CHECK and is absent from ArtifactCreate. Resolved: default
     kind = 'upload' server-side for owner uploads (later tasks set richer kinds for tool evidence).
  3. No `/preview` path exists in the frozen contract; T07 requires a safe preview. Added
     `GET .../artifacts/:artifactId/preview` returning a bounded, escaped, redacted JSON preview.
  4. Idempotency-Key is contract-required on the mutating routes; T07 requires idempotent finalize.
     The finalize state machine is naturally idempotent (pending->ready once); the header is required
     for contract compliance (400 if absent) but not yet persisted for create-dedup (see risks).

OPEN RISKS + MINIMAL NEXT STEP
  - Idempotency-Key is required but not stored, so a retried createUpload makes a second pending row
    (cheap; swept by reconcile). Next step: a small idempotency table keyed by (route, key) in T09.
  - Disk-full was exercised via an ENOTDIR-class IO failure (parent path is a file), which is
    root-independent and reliably reproduces "no partial ready"; a true ENOSPC needs a size-capped
    tmpfs in the deployment lab (T28/T31).
  - reconcile() sweeps orphans/stale staging on demand; wiring it to the `artifact_reconcile`
    maintenance job (migration-0002 kind) is a runtime-scheduler task (T13+).
  - Health deep-liveness probe of the ObjectStore (D03) is not wired here; env.objectStoreRoot
    presence still gates mounting. Next step: add an ObjectStore ping to readiness in a health task.
