# Implementation decisions

Durable record of spec-conflict resolutions and choices that later tasks must
respect. Architecture-level changes get an ADR under [`adr/`](../adr); this file
captures the smaller decisions and rationale.

| ID | Decision | Rationale | Affects |
|---|---|---|---|
| D01 | `specs/` is kept intact as the **frozen input package** (its MANIFEST/SHA256SUMS integrity stays valid). The single **edited** canonical contract source lives at repo root (`contracts/`, `db/`, `catalogs/`, `prompts/`, `AGENTS.md`, `SPEC_LOCK.json`, merged `docs/` & `implementation/`). | Architecture §10 forbids two *edited* contract sources but frames `specs/` as the input reference package. Copying (not moving) preserves provenance while giving one live source. | All contract/DB/codegen consumers read the root copies. |
| D02 | `apps/web` is a compiling **placeholder** in M0; the real Next.js app (routes, SSE client, Workbench shell) is scaffolded in **T10**. | Keeps the M0 build fast and offline-reproducible; T10 is the UI milestone and owns the web app. Health surface lives in `apps/api` per architecture §1. | T10 (UI). |
| D03 | Health readiness rule (`unconfigured` / `degraded` / `ready`) is implemented as **pure domain logic** in `@redai/domain` and rendered by `apps/api`. In M0 `healthy` mirrors configuration presence; **deep liveness probes** (real DB/ObjectStore connections) are wired when those components land (T02, T07). | Architecture: domain owns rules, apps render. Honest health: never claim a component healthy without verifying it. | T02, T07 set `healthy` from real checks. |
| D04 | PostgreSQL migrations are authored and **verified on the pinned test server (16.13)**. `SPEC_LOCK` target major is 18; nothing is marked verified on 18 until a pinned 18 server exists. Migrations avoid PG17/18-only syntax until then. | Reference environment ships PG16; the spec targets PG18. Recorded in `docs/dependency-baseline.md`. | T02 re-runs fresh+upgrade smoke on PG18 when available. |
| D05 | Generated **Go contract types must be plain structs with no third-party dependencies** (no additions to `worker/go.sum`). | Keeps the worker module dependency-light and avoids codegen-tool supply chain in the worker; TS side may use a codegen tool. | T03. |
| D06 | **T04 delivers API-side auth only** (bootstrap CLI, sessions, cookie/CSRF/Origin, rate limit, logout/reset/revoke) with full tests. The **login/`/setup` UI is deferred to T10** alongside the Next.js app (consistent with D02). | User-chosen (M1 kickoff): keep startup offline/fast; UI milestone owns the web app. Auth correctness lives in API + application layers where it is testable without a browser. | T04 (API), T10 (login UI). |
| D07 | The **installation signing key** echoed in the worker enrollment response (contract: ≥1 trusted key) is generated **at API process start** (in-memory Ed25519) for M1 wiring; persistent installation-key management (rotation, retirement, the signer) is a later payload-signing task. Stable for the process lifetime, which is enough before any long-lived worker exists. | Unblocks worker-enroll wiring without pulling the full signing subsystem into M1. No persistent worker exists yet, so process-lifetime stability suffices. | Payload-signing task (persistent keys). |
| D08 | The **`@redai/application` sub-modules** (settings, projects, workerIdentity) are exposed via **package subpath exports** (`@redai/application/settings`, `/projects`, `/workerIdentity`) rather than a single flat barrel. | The modules re-export overlapping helper names (`systemClock`, `constantTimeEqual`, `Clock`, `RandomSource`); subpaths keep flat names without collisions and let the coordinator wire them with minimal churn. | All API consumers. |
| D10 | **M2 UI API gaps** to close in later tasks (not blocking M2 dev-alpha): (a) add an unauthenticated `GET /api/v1/auth/bootstrap-state {owner_exists}` so `/setup` can tell "no owner yet" from "not signed in"; (b) an owner-facing worker LIST API; (c) browser password-change / session-list-revoke (today host-CLI only). | T10a surfaced these while wiring real screens; each is a small additive endpoint, deferred to keep M2 moving. | T04-followup / T15-followup / identity task. |
| D11 | **SSE wire contract** (T11): frames are `id:`=event_id, `event:`=type, `data:`=full envelope; two control frames — `stream.cursor` (has id, advance-only) and `stream.resync` (no id: `cursor_expired`→snapshot+new connection, `slow_consumer`→reconnect). Expired cursor returns a 200 in-band resync frame (NOT 410) because a bare EventSource can't read a non-2xx body. A full authenticated browser↔API SSE e2e is a follow-up (both sides currently proven by unit + raw-http/mock tests). | Aligns T11 backend and T10b client; keeps EventSource auto-reconnect working. | Follow-up e2e (T30/T34). |
| D12 | **T16 worker daemon** distinguishes two renewal cadences that docs/08 names close together: (a) the **per-attempt lease** renew (`worker_renew_seconds`=10s within a 45s lease) is a T17/scheduler concern and is NOT implemented here — only the Scheduler seam is; (b) the **worker credential** renew-before-expiry (30-day `worker_credential_ttl_seconds`) IS owned by the supervisor, scheduled from the credential's own TTL minus a margin (default 24h), with bounded retry backoff. The journal enforces a **strict-forward phase order** (received<prepared<start_intent<started<uploading<settled); an unproven outcome settles as `unknown` (terminal, never replayed, never reported success) per docs/08 §6/§9. Spool bound is **backpressure (refuse `ErrSpoolFull`)**, not silent eviction of un-ACK'd evidence; release is caller-driven after a durable upload ACK (docs/08 §5 step 8). | docs/08 mixes lease-renew and credential-renew wording in the "heartbeat + renew" loop; conflating them would either drop credential rotation or wrongly implement lease renewal before the claim plane exists. Evicting un-ACK'd evidence to stay under budget would lose forensic bytes; refusing is the fail-closed choice. | T17 (lease renew + claim/result via Scheduler/SessionContext), T18 (sandbox). |
| D13 | **T12 scope engine choices:** (a) the DNS challenge binds to the columns the migrated immutable `dns_proofs` table actually has (+`challenge_hash UNIQUE`); per-version binding to `installation_id`/`requested_version` needs a later migration if required. (b) Public-suffix handling uses a small built-in fail-closed denylist, not the full PSL (swappable). (c) `policy_sha256` uses deterministic sorted-key JSON, not full RFC 8785 JCS — revisit if Go-parity JCS is needed. (d) A "lab rule" (`lab_attestation`, no DNS) is one declaring non-empty `lab_ip_ranges`. (e) `createDbScopeService` lives in `@redai/application/scope` (not apps/api) so the api package builds before the coordinator adds the subpath export; `@redai/policy` imports nothing external (import-boundary stays green). | Ambiguities/deviations surfaced by T12; each is fail-closed and swappable, none widens authority. Verification always uses a trusted resolver, never the target's HTTP. | Later migration for per-version challenges; PSL/JCS upgrades if Go parity needs them. |
| D09 | **DB-backed integration tests** (`tests/integration/db/**`, `packages/*/**/dbRepository.test.ts`) are executed by **Vitest (esbuild), not type-checked by `tsc -b`**; they import package source by relative path (matching the T02 pattern) and skip loudly without `DATABASE_URL`. A dedicated test typecheck can be added in T33 (CI hardening). | These tests cross package boundaries (shared throwaway-DB helper) and must not sit inside a composite project's `rootDir`. Vitest already runs them; tsc build stays clean. | T33 (optional test typecheck). |
